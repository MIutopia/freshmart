# 交易与模拟支付

首期交易使用 `freshmart_trade` 记录交易单、商家子订单、订单项、库存预占、支付单和费用台账。商品、批次和配送任务分别仍归属商家库与配送库。

## 创建交易

交易请求传入配送区域、地址快照与按克计量的商品行，并且必须携带 `Idempotency-Key`。服务端读取已上架商品、市场价、商家价、仓配规则和批次库存；前端价格不会参与结算。

1. 依据配送区域和分类仓配优先级为每个商品选择仓库。
2. 同一商家存在多个不同仓库时，拒绝该交易，避免跨仓拆分。
3. 按商家生成履约子订单，并分别计算商品金额和配送费。
4. 以先进临期批次优先顺序锁定库存，并将预占记录设置为 15 分钟后到期。
5. 保存用户价、商家应收价和平台价格补贴快照；用户价不高于市场价，商家价上限为市场价的 105%。

## 本地模拟支付

`POST /api/payments/{tradeNo}/prepay` 返回 `SIMULATED://` 扫码地址，不调用微信。`POST /api/payments/{tradeNo}/confirm-simulated` 只能由交易所属用户调用，且必须在预占到期前完成。

确认成功后，系统扣减已预占批次库存、交易单改为 `PAID`、商家子订单改为 `WAITING_PICKING`，并在配送库创建一条状态为 `WAITING_ASSIGNMENT` 的任务。该操作通过同一 MySQL 实例的单连接事务执行；生产拆库后须改为事件 outbox 与补偿机制。

库存预占释放任务每 60 秒扫描一次到期交易；到期后回退批次的 `reserved_grams`、将预占记录标记为 `RELEASED`、取消交易和子订单，并将待支付模拟支付单标记为 `EXPIRED`。可通过 `INVENTORY_RELEASE_INTERVAL_MS` 调整扫描间隔。

当前版本仍未实现余额扣款、微信商户号回调和退款；优惠叠加、会员折扣和优惠券核销已接入下单结算，并写入交易及商家子订单价格快照。余额支付、真实微信回调和退款接入时不得绕过现有库存锁定、优惠券状态和金额快照规则。
