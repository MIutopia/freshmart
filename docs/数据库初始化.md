# 数据库初始化

## 已验证环境

- MySQL 8.0.46 安装于 `E:\mysql-8.0.46-winx64`。
- 用户提供的终端截图表明 `root` 可登录 `127.0.0.1:3307`。
- 本轮 TCP 检查已确认 `127.0.0.1:3307` 可达。

## 初始化顺序

1. 使用数据库管理员账号在 MySQL 客户端执行 `backend/scripts/bootstrap-database.sql`，并将其中示例密码替换成仅用于本机开发的强密码。
2. 使用数据库管理员账号执行 `backend/scripts/bootstrap-domain-databases.sql`，创建用户、商家、配送、交易费用和日志五个业务库及当前结构基线。
3. 将相同账号密码填入本机未提交的 `backend/config/application-local.yml` 的 `db.username`、`db.password`。`DB_USERNAME`、`DB_PASSWORD` 环境变量可用于临时覆盖本地配置。
4. 启动 Spring Boot。Flyway 会连接 `freshmart` 数据库并执行 `V1__init.sql`。
5. 确认 `flyway_schema_history` 与业务表已创建。V8 会预置用户、商家和配送员各 10 个本地测试账号，账号规则见 [本地测试账号.md](本地测试账号.md)。启动时会自动检查五个卫星库的必需表和关键列。

V2 迁移增加交易单、库存预占、个人微信收款码支付、退款、用户券和站内消息表。`trade_orders` 是一次多商家结算的支付聚合单，`orders` 是按商家拆分后的履约子订单。

V3 迁移增加后台可编辑的平台规则与售后策略。配送费门槛、标准配送费、预占时长、称重误差上限和售后窗口均以 `platform_rules`/`refund_policies` 为最终来源，环境变量仅作为应用启动前的兜底配置。退款证据保存在 `refund_orders.evidence_images_json` 和 `evidence_description`，问题类型由 `issue_type` 限定。

V4 迁移增加账号密码、商家入驻审核、平台佣金、固定配送区域、余额账户、会员等级、积分、可叠加促销、平台骑手超时与绩效字段。首期扫码支付仅保留个人微信收款码适配边界，本地不要求商户号和域名回调。

V23 将已有支付单默认值迁移为 `PERSONAL_WECHAT_QR` / `MANUAL_CONFIRMATION`。V24 增加支付备注、付款凭证、人工核验记录、微信账单导入及流水、对账差异表，并为退款单增加人工退款工单状态、操作人、完成时间和失败原因。执行账单导入或人工退款确认前，应先确认管理员权限并保留审计日志。

V27 对齐卫星库结构契约：用户权益表、商家促销和仓配规则表、交易库存预占/电子小票/批次分配/退款/称重表，以及站内消息 SVG 内容字段。V26 对配送任务补充接单超时字段。V29 补齐历史数据库中个人收款码支付单的 `code_url` 字段；V30 创建媒体资产审计表并启用上传访问控制。

V31 增加积分抵扣字段（`trade_orders`/`orders` 的 `redeemed_points`、`points_discount_amount`）。V32 为退款库存处置补充处理人、处理时间与处理备注。V33 增加配送接单超时规则 `delivery.accept.timeout.minutes`。V34 在 `freshmart_log` 增加 AI 交互审计表 `ai_interaction_logs`，只保存请求与响应的 SHA-256 摘要及元数据。V35 为商家结算补充确认人与结算备注。V36 在 `freshmart_user` 增加用户通知偏好表，在 `freshmart_log` 增加节气/节日卡片任务与投递记录表，并为站内消息补充幂等键 `idempotency_key`。

主库 `freshmart` 承载平台规则（`platform_rules`）、售后策略、Flyway 历史与尚未迁移的兼容遗留表；`bootstrap-domain-databases.sql` 只负责五个卫星库的表基线，不重复定义主库对象。

`bootstrap-database.sql` 只负责创建数据库和应用账号；Flyway 迁移只负责连接后的表结构演进，二者不可混用。

## Flyway 失败迁移恢复

MySQL 的 DDL 不支持事务回滚。若启动报错指出 `flyway_schema_history` 存在 `success = 0` 的失败版本，先备份本地开发数据库，并检查该版本所涉表、列和索引是否已经部分创建。修复迁移脚本为可重复执行后，删除该失败记录，让 Flyway 在下一次启动时重新执行该版本：

```sql
USE freshmart;

SELECT installed_rank, version, description, success
FROM flyway_schema_history
WHERE version = '14';

DELETE FROM flyway_schema_history
WHERE version = '14' AND success = 0;
```

不得将失败记录手工更新为 `success = 1`，也不得跳过未实际执行的版本。V14 已使用 `information_schema` 动态判断列和索引，兼容 MySQL 8.0 的部分执行重试场景。

## 数据安全

- 不提交 `.env`、真实数据库密码、微信支付密钥、回调证书或 AI 提供商密钥。
- 开发环境应用账号仅授予 `freshmart.*` 范围的权限，不使用 root 作为 Spring Boot 运行账号。
