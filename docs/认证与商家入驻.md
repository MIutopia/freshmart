# 认证与商家入驻

## 认证模型

首期使用账号密码登录。密码只保存 BCrypt 哈希，认证成功后服务端生成 32 字节随机 Bearer Token；数据库只保存 Token 的 SHA-256 哈希、到期时间和吊销时间。默认会话有效期为 8 小时，可通过 `AUTH_SESSION_HOURS` 修改。

每次请求校验用户状态、会话未吊销且未到期，并加载用户角色。首期角色为 `CONSUMER`、`MERCHANT`、`RIDER` 和 `ADMIN`。一个用户可有多个角色；商家入驻审核通过后，申请人增加 `MERCHANT` 角色，不移除消费者角色。

## 商家入驻流程

1. 消费者登录后提交商家名称和营业执照材料地址。
2. 系统创建状态为 `PENDING` 的商家和入驻申请；同一申请人有待审核申请时不能重复提交。
3. 管理员查看待审核申请，填写审核说明并通过或驳回。
4. 通过时商家状态改为 `ACTIVE`，申请人授予 `MERCHANT` 角色；驳回时商家状态为 `REJECTED`。

登录、登出、提交申请和审批都会写入 `audit_logs`。审计记录包含操作人、动作、业务对象、来源 IP 和发生时间；Token 明文、密码和营业执照内容不写入审计字段。

## 本地初始化

Flyway V7 创建 `auth_sessions` 与 `audit_logs`。本地首次创建数据库时运行 `backend/scripts/bootstrap-database.sql`，它同时授权 `localhost` 与 `127.0.0.1` 连接。

管理员账号不写死在迁移文件中。应在本地环境使用 BCrypt 哈希创建管理员用户，并为其插入 `ADMIN` 角色；生产环境须通过受控运维流程完成，不得将初始密码提交到 Git。
