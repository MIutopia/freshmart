# 价格与仓配结算规则

## 价格口径

商品按千克维护市场参考价 `M` 和商家上架价 `L`，商家上架时必须满足 `L <= M * 1.05`。实际履约重量为 `W` 克。

| 字段 | 计算规则 | 结算含义 |
| --- | --- | --- |
| 用户标准单价 | `min(L, M)` | 用户未参与营销前的商品单价；商家价高于市场价时，用户仍按市场价支付 |
| 平台价格补贴单价 | `max(L - M, 0)` | 商家价在合规上浮范围内高于市场价时，由平台支付给商家的差额 |
| 商家商品毛额 | `L * W / 1000` | 商家按实际重量可结算的商品毛额，保留到订单项快照 |
| 用户商品金额 | `min(L, M) * W / 1000` | 用户在营销优惠前应付的商品金额 |
| 平台价格补贴金额 | `max(L - M, 0) * W / 1000` | 平台承担的价格差额，不计入用户应付金额 |

全部金额按人民币元保存，逐订单项四舍五入到两位小数。商家价不高于市场价时，用户标准价等于商家价，平台价格补贴为零。

## 支付、优惠与结算

1. 后端根据商品、实际重量和上述价格规则计算用户商品金额，前端报价只用于展示。
2. 优惠按已确认顺序执行：会员折扣、满减、优惠券、积分抵扣；秒杀价与普通折扣互斥。每笔优惠必须记录承担方为商家或平台。
3. 用户支付金额等于用户商品金额减去全部可用优惠，再加配送费；余额支付成功或管理员确认个人收款码到账后才进入待分拣。
4. 商家结算前金额等于商家商品毛额减去商家承担的优惠。平台承担的优惠和平台价格补贴不减少商家应收。
5. 平台佣金基数为商家商品毛额扣除商家承担优惠后、再扣除平台价格补贴的金额；平台价格补贴不计佣。商家净结算金额等于商家结算前金额减佣金。
6. 平台成本包含平台价格补贴、平台承担优惠、称重差额承担和退款损失，并按订单、商家和优惠活动记录可追溯快照。

## 仓库经营分类与仓配规则

仓库先配置“可经营分类”，例如某仓库只允许经营水果和冷藏乳品。商家再按“商家 + 商品分类 + 仓库”设置有效仓配规则和优先级。

批次入库、商品上架选仓和订单选仓必须同时满足以下条件：仓库归属该商家、仓库位于用户配送区域、仓库已启用该商品分类、商家已配置有效分类仓配规则。缺少任一条件时，系统拒绝入库或结算，不自动跨仓、跨区域或跨商家拆分。

多商家交易单先按商家拆分子订单，再在每个商家子订单内校验单仓、单配送区域和分类仓配规则。每个商家子订单独立生成配送任务。

## 本地支付边界

本地使用统一支付/退款适配器接口，工厂首期固定返回个人微信收款码实现。系统不会从个人收款码自动获知支付结果，用户付款备注必须包含订单号；付款截图审核或账单导入匹配成功后才可标记支付成功，并记录核验人、金额、备注和凭证。账单无法匹配、金额不一致、备注缺失均进入对账差异，不自动放行。

个人收款码退款不调用微信接口。客服审核通过后生成 `PENDING_MANUAL_REFUND` 工单，管理员完成转账并确认后才把退款单和原订单改为已退款；失败时保留失败原因并允许后续重试。支付核验、账单导入、人工退款确认均写入审计日志。

微信商户号签名验真、异步支付回调和原路退款回调仅保留统一接口的后续实现边界。个人收款码仅用于本地测试或小范围验证，正式经营存在收款限制、资金冻结和伪造截图风险。
