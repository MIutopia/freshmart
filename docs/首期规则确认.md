# 首期规则确认

根据已确认方向，首期规则固化如下：

| 领域 | 首期规则 |
| --- | --- |
| 商家 | 支持多商家入驻；平台审核后营业；商家隔离管理商品、库存和订单 |
| 价格 | 统一市场价按千克展示；订单项保存下单时单价快照；实际称重以克记录，金额按 `克数 / 1000 × 元/千克` 计算 |
| 库存 | 下单时预占克数；支付成功转扣减；超时未支付释放预占；缺货进入售后处理 |
| 配送 | 平台统一派单；配送员只能接收分配任务；状态为待派单、已接单、已取货、配送中、已送达、异常 |
| 支付 | 首期接入微信 Native 扫码支付；支付回调幂等；支付成功才生成分拣任务 |
| 退款 | 支持整单和按商品项退款；退款回调幂等；是否回补库存取决于是否已取货 |
| 优惠券 | 支持平台券和商家券；默认一单一券、不可叠加；按门槛和有效期校验 |
| AI 导购 | 依据用户需求、预算、忌口、时令和节气推荐；只读商品/库存/订单查询，不直接执行交易写操作 |
| AI 经营分析 | 向商家输出销量、客单价、复购、库存预警和时段趋势摘要；结果需标注统计周期 |
| SVG 卡片 | 节气/节日触发模板化 SVG 卡片；文案和商品推荐由 AI 生成，颜色、尺寸和安全区域由模板约束；发送前保留预览和审计记录；首期仅发送站内消息 |

## 本机开发环境

- MySQL 安装目录：`E:\\mysql-8.0.46-winx64`
- MySQL 端口：`3307`
- Spring Boot 默认连接：`jdbc:mysql://127.0.0.1:3307/freshmart`
- 连接验证：根据用户提供的终端截图，`root` 已成功登录 MySQL 8.0.46 的 `3307` 端口；密码不写入项目。

## 已确认的首期参数

- 微信支付模式：Native 扫码支付。
- 未支付库存预占：15 分钟，超时由释放任务回补可售库存。
- 配送费：平台统一按订单优惠后商品金额计算，默认满 `59.00` 元免配送费，否则 `6.00` 元。
- 称重误差：实际金额低于预估时退回差额；高于预估且差额不超过 `1.00` 元由平台承担，超过上限转人工审核。
- 节气/节日卡片：首期仅通过站内消息发送。

## 仍需确认的参数

1. 配送费的 `59.00` 元免配送门槛和 `6.00` 元标准费用是否符合平台实际规则？
2. 称重误差平台承担上限 `1.00` 元是否符合财务要求？
3. 退款申请时限和品质问题举证材料要求是什么？
4. 多商家订单是否允许跨商家合并配送，还是必须按商家拆分配送任务？
