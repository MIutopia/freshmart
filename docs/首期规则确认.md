# 首期规则确认

根据已确认方向，首期规则固化如下：

| 领域 | 首期规则 |
| --- | --- |
| 商家 | 支持多商家入驻审核；平台审核后营业；商家隔离管理商品、库存和订单；平台按规则抽取佣金并生成结算记录 |
| 价格 | 统一市场价按千克展示；商家上架价不得超过市场价 `5%`；超出市场价的差额由平台承担；订单项保存单价快照；实际称重以克记录 |
| 库存 | 下单时预占克数；支付成功转扣减；超时未支付释放预占；缺货进入售后处理 |
| 仓储 | 一个商家可配置多个仓库；仓库绑定唯一商家和固定配送区域；每个商家子订单只允许单仓、单区域，不自动跨仓/跨区域拆单 |
| 配送 | 平台统一派单；配送员只能接收分配任务；不同商家分别生成配送任务；状态为待派单、已接单、已取货、配送中、已送达、异常 |
| 支付 | 首期支持余额支付和微信 Native 扫码支付；本地默认模拟支付，测试时可展示个人微信收款码并由运营人员人工确认支付；商户号回调仅保留为后续适配器草案 |
| 退款 | 首期仅支持缺货和品质问题；默认送达后 `1` 天内申请；图片加描述；由平台客服和 AI 辅助审核 |
| 优惠与会员 | 支持优惠券、满减、会员等级、积分和秒杀；优惠允许叠加，后端按优先级和封顶规则计算并保存快照 |
| 追溯与促销 | 按仓库和批次出库，订单项保留批次分配；临期批次默认提前 3 天进入低价促销候选；生成电子小票快照 |
| 开放 API | 为审核商家或合作方开放只读商品、库存、订单、小票和批次追溯接口；按客户端密钥、范围和商家边界授权 |
| AI 导购 | 依据用户需求、预算、忌口、时令和节气推荐；支持订单查询；只读商品/库存/订单查询，不直接执行交易写操作 |
| AI 经营分析 | 首期建设商家经营数据看板，不调用 AI 生成分析结论；后续版本在看板数据和统计口径稳定后接入 AI 分析能力 |
| SVG 卡片 | 节气/节日触发模板化 SVG 卡片；文案和商品推荐由 AI 生成，颜色、尺寸和安全区域由模板约束；发送前保留预览和审计记录；首期仅发送站内消息 |

## 已确认的首期参数

- 微信支付模式：Native 扫码支付。
- 未支付库存预占：15 分钟，超时由释放任务回补可售库存。
- 配送费：平台统一按订单优惠后商品金额计算，默认满 `59.00` 元免配送费，否则 `6.00` 元；门槛和费用由管理后台配置并记录操作日志。
- 称重误差：实际金额低于预估时退回差额；高于预估且差额不超过 `1.50` 元由平台承担，超过上限转人工审核。
- 售后时限：首期统一为骑手送达后 `1` 天内；申请必须上传图片并填写描述。
- 售后范围：仅支持缺货、品质问题；运输途中损坏仅作为品质问题的证据类型，其他问题暂不开放。
- 多商家履约：一个交易单按商家拆分子订单，每个商家独立生成一个配送任务，不跨商家合并配送。
- 节气/节日卡片：暂列后续版本；首期 AI 仅实现导购和订单查询。

## 非阻塞默认参数

1. 配送费默认满 `59.00` 元免配送、否则 `6.00` 元，后台可修改。
2. 平台默认佣金比例为 `10%`，后台可按类目或商家修改。
3. 优惠叠加默认顺序为会员折扣 -> 满减 -> 优惠券 -> 积分抵扣，秒杀价与普通折扣互斥。
4. 当前只建设网页端，不建设小程序和 App。
5. 首期容量目标为日订单量 `50` 单、并发用户 `20` 人；图片或视频单文件上限为 `30 MB`。
