## 恢复为标准 Git 布局

在具有本机文件权限的开发终端中，先删除本轮生成且没有提交的根目录 `.git`，再将临时版本库连接到项目根目录：

```powershell
Remove-Item -LiteralPath .git -Recurse -Force
git --git-dir=work/freshmart.git --work-tree=. config core.worktree "$(Get-Location)"
Set-Content -LiteralPath .git -Value "gitdir: work/freshmart.git"
git status
```

## 绑定 GitHub 并推送

先在 GitHub 创建一个空仓库，不勾选 README、`.gitignore` 或 License。以仓库地址 `https://github.com/<owner>/freshmart.git` 为例：

```powershell
git remote add origin https://github.com/<owner>/freshmart.git
git branch -M main
git push -u origin main
```

若仍使用临时版本库，则每条命令前加上 `git --git-dir=work/freshmart.git --work-tree=.`。GitHub 的账户认证、组织选择、仓库可见性以及令牌应由仓库拥有者在本机完成，不应写入项目文件或技术文档。

## 分支约定

- `main`：已验证、可演示的版本。
- `feature/<module>-<topic>`：单项功能，例如 `feature/order-checkout`。
- `fix/<topic>`：缺陷修复。
- 每个提交只覆盖一个明确意图；涉及状态机、金额、库存或权限的修改，必须同步更新相关 `docs/` 文档。

## 模块开发隔离约束

开发任何功能模块时，必须从最新 `main` 创建独立分支，禁止直接在 `main` 上开发、提交或调试性修改。不同模块使用不同分支，互不覆盖主分支架构：

```powershell
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c feature/<module>-<topic>
```

模块分支完成后，必须通过对应测试、静态检查和文档校验，再以 Pull Request 合并回 `main`。合并前不得使用 `--force` 覆盖远程分支；未完成模块保留在自己的分支，不回写主分支。推荐的模块分支示例：

- `feature/auth-password-login`
- `feature/merchant-onboarding`
- `feature/catalog-inventory`
- `feature/trade-wallet-payment`
- `feature/delivery-rider-performance`
- `feature/ai-guide-order-query`

每个功能分支只负责一个业务边界；跨模块变更需要在 PR 描述中列出依赖关系和回滚方式。`main` 只接受已验证、可演示的合并提交。
