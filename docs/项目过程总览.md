# FreshMart 项目过程总览

本文按需求确认、架构设计、规则固化、代码实现、验证和后续计划整理项目全过程。代码和提交历史是实现事实来源；规则说明以本目录其他专题文档为准。

## 1. 初始目标

项目题目为“基于 Spring Boot + Vue 的生鲜果蔬配送商城系统的设计与实现”。技术路线确定为 Java 17、Spring Boot 3、Vue 3、MySQL 8，采用前后端分离、模块化单体起步，并预留 AI Gateway 和后续服务拆分边界。

首期网页端按四类业务端组织：用户端、商家端、平台管理后台、平台配送员端。AI 首期只做智能导购和订单查询；商家经营分析先做数据看板，后续再做 AI 分析。

## 2. 需求逐步确认

1. 支持多商家入驻，商家先审核后营业；平台抽取佣金并生成结算记录。
2. 平台统一配送，配送区域为固定区域，配送员为平台自有人员；按商家生成子订单和独立配送任务。
3. 商品按重量计价，市场价和商家价按千克维护，实际重量按克记录；商家价不得超过市场价 5%，合规上浮差额由平台承担。
4. 支付首期支持余额和个人微信收款码；本地展示个人收款码并由管理员人工确认到账，不接商户号回调和域名回调。
5. 下单预占库存 15 分钟，超时释放；配送费按平台统一规则计算，默认满 59 元免配送，否则 6 元，规则可配置。
6. 售后首期仅缺货和品质问题；运输损坏只能作为品质问题证据。送达后 1 天内申请，必须上传图片并填写描述，由客服和 AI 辅助、客服最终确认。
7. 支持优惠券、满减、会员等级、积分、秒杀，优惠可叠加；秒杀价与普通折扣互斥。多仓库按商家和仓库边界限制，不跨仓、跨区拆单。
8. 支持电子小票、批次追溯、临期 3 天低价促销候选、站内消息和只读开放 API；暂不做小程序和 App，单个图片/视频不超过 30 MB。
9. 首期容量目标为日订单 50 单、并发用户 20 人。

## 3. 架构与协作决策

- 采用 `freshmart_user`、`freshmart_merchant`、`freshmart_delivery`、`freshmart_trade`、`freshmart_log` 五个 Schema，均在本机 MySQL `127.0.0.1:3307`；跨库只用业务 ID，不建跨库外键。
- 认证采用账号密码、BCrypt、Bearer Token、角色和审计日志；本地用户、商家、配送员各 10 个账号，统一测试密码为 `password`，另有管理员账号 `admin-test-01`。
- GitHub 远程仓库为 `https://github.com/MIutopia/freshmart`，已完成 CLI 授权和仓库创建。历史五个功能分支已全部并入 `main` 并从本地与远程删除，仓库收敛为单一 `main` 分支；`main` 只接收完整验证版本，后续功能按 `docs/版本控制与协作.md` 的「模块开发隔离约束」从最新 `main` 拉独立分支开发，完成后经 Pull Request 合并。
- 每次策略、规则、开发、优化和测试都必须写入 [开发变更日志](开发变更日志.md)，失败结果也保留。

## 4. 已完成实现

### 后端与数据

- 认证、角色权限、商家入驻申请/审核、审计日志。
- 五库数据源配置和初始化脚本，含测试账号、用户地址、余额账户、营销表、仓库和配送表。
- 商品分类、商品、仓库、批次库存、仓库可经营分类、商家分类仓配规则和市场价校验。
- 固定配送区域、管理员派单、骑手接单超时回池、取货、送达和绩效统计。
- 多商家交易单、商家子订单、单商家单仓约束、批次库存预占、个人收款码支付适配器、支付确认扣库存、费用台账和超时释放。
- 会员等级、积分计算、积分流水；优惠券创建、领取、下单预占、支付核销和超时释放；会员折扣与优惠券优惠快照。
- 支付确认时将批次预占固化为订单项实际出库批次分配；支付后按订单生成不可变电子小票，并按用户、所属商家和管理员边界提供批次追溯查询。
- 开放 API 基础鉴权：管理员创建客户端、一次性明文密钥、BCrypt 哈希、scope/有效期/商家边界校验、访问日志和商品只读查询。
- 开放 API HMAC 与只读闭环：时间窗、nonce 防重放、商品/库存/订单/小票/批次追溯查询均已实现。
- 临期批次折扣已接入下单：按实际预占批次克数计算额外优惠，保存预占和出库分配快照，商家毛收入与市场价补贴口径不变。
- 价格纯函数、运费、称重差额、仓库边界和媒体大小策略测试。
- 本地媒体资产：上传限 JPEG、PNG、WebP、MP4、MOV 且单文件不超过 30 MB，落盘为随机存储名并按受保护 URL 提供下载；付款凭证与售后证据必须引用当前用户上传的图片，仅资金审核角色可读。
- 积分抵扣：1000 积分抵 1 元、仅抵商品金额、单笔最高抵扣优惠后商品金额的 3%；下单冻结、超时释放，退款不返还已抵扣积分但仍按原规则回退该订单已发放的消费积分。
- 售后库存检验处置：退款后按处置单记录回库或报损，留存处理人、处理时间与处理备注。
- 售后 AI 辅助审核：调用受控模型生成审核建议，仅作客服参考，不代替人工结论。
- AI 交互摘要审计：`ai_interaction_logs` 只保存请求与响应的 SHA-256 摘要及元数据，不落原文。
- 配送接单超时规则后台化：`delivery.accept.timeout.minutes` 纳入平台规则表读取。
- 商家结算确认：结算单由运营或财务确认，并留存确认人与确认备注。
- 节气/节日卡片自动投递：新增用户通知偏好、卡片任务与投递记录三张表，站内消息以幂等键去重，失败任务进入下一轮自动重试。

### 前端与视觉资产

- Vue 3 + Vite 前端壳，提供 `/app`、`/merchant`、`/delivery`、`/admin` 四端入口切换和模块占位展示。
- 已生成 FreshMart Logo、Logo mark 以及购物车、看板、配送、果蔬、定位、订单等 SVG 2D 图标，位于 `outputs/fresh-market-assets/`；尚未接入完整业务页面。
