# 待确认问题

这些问题会影响表结构、状态机和接口参数。请按优先级回复，未确认前按文档中的保守默认值推进。

## P0：必须先定

1. 商城是单商家自营，还是多商家入驻平台？若多商家，是否需要商家入驻审核、平台抽佣和商家结算？
2. 配送范围如何定义：固定区域、地图半径，还是按行政区/配送站？是否需要同城即时配送？
3. 支付方式需要哪些：微信/支付宝、货到付款、余额？是否已有支付商户号和回调域名？
4. 生鲜计价是否同时支持按件与按重量？称重后产生的差额如何处理？
5. 库存采用“支付扣减”还是“下单预占、超时释放”？预占时长是多少？
6. 售后规则是仅支持缺货/品质问题，还是支持无理由退款？申请时限、举证材料和审核角色是什么？

## P1：影响首期体验

1. 用户是否需要手机号登录、短信验证码、微信登录或纯账号密码？
2. 商家端是否需要独立店铺首页、营业时间、起送金额和配送费模板？
3. 配送员是平台自有还是商家自有？是否需要抢单、派单、接单超时和绩效统计？
4. AI 首期优先做导购、客服、订单查询还是商家经营分析？是否允许联网搜索？
5. 是否需要优惠券、满减、会员等级、积分和秒杀？优惠是否可叠加？

## P2：后续增强

1. 是否需要多仓库、区域库存和跨仓拆单？
2. 是否需要发票、电子小票、批次追溯和临期促销？
3. 是否需要开放 API、小程序端或 App 端？
4. 预计日订单量、并发用户量和图片/视频存储量级是多少？

## 保守默认值

在收到回复前，架构按“平台自营、按件计价、支付后扣库存、固定配送区域、平台派单、手机号登录、AI 只读查询与推荐”设计；不接入真实支付和模型密钥，不发布生产环境。
